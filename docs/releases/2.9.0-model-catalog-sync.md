# JJDGuard 2.9.0 模型目录同步

通用 OpenAI 兼容渠道沿用模型上游页的同步入口。刷新目录同时清理明确由同步管理的失效来源；勾选决定新模型的协议探测与纳入，不阻止完整目录的失效清理。周期默认一小时，可在同一弹窗关闭或设置 5 分钟、1 小时、6 小时、一天。周期任务只读取目录，不执行推理探测，新增项为待纳入。协议证明过期或配置变化后显示未验证，需使用现有验证入口更新证明。

勾选同步的探测耗时（2026-10-29 起）：勾选的模型同时探测 4 个（每个文本模型探 chat 与 responses，图片模型真生成一张图）。已纳入、且探测证据还有 1 天以上有效期、并在当前渠道配置（类型、地址、鉴权方式）下取得的模型，再次勾选时沿用上次证据，不重复调用上游，回执里计入「沿用验证」。证据过期、渠道地址或鉴权方式改了、或从未验证过的模型照常探测。要强制重新验证某个模型，用模型管理页的「验证」按钮。

同步目录必须返回 HTTP 200、有限长度完整 JSON、明确的 data 数组和有效模型 ID。只有该完整数组为空才表示合法空目录。error 信封、missing/null data、超时、401/403/429/5xx、无效 JSON、矛盾 total、has_more 或未完成分页均失败并保留上次有效状态。目前通用连接器对尚未实现完成证明的分页响应拒绝同步，不能把第一页当完整目录。不支持枚举、完整 Chat、人工维护及 Azure 显式验证流程沿用既有接入方式。

模型 ID 和公开别名保持稳定。失效来源标记 upstream_removed，人工禁用保持 disabled，新增默认 pending；人工模型和归属不明的历史配置不会被隐式收编或删除。重新出现恢复同步关联；仅由同步移除的启用状态可以恢复，人工禁用、待纳入以及人工协议覆盖保留。模型行、审计和用量数据不删除。迁移仅接管模型创建时间与同步创建审计批次严格对应、数量相符且没有人工创建审计的旧记录；其他历史来源必须用可信记录核对后由操作人员处理。

可调用视图同时检查模型/渠道启用、有效凭据、协议有效证明、当前渠道配置、目录归属状态和健康状态。协议依据区分真实验证、人工确认和未验证。地址策略阻止探测等未实际到达上游的结果记为未知；实际鉴权、限流、超时或上游故障进入临时探测失败。未知健康不会冒充探测成功；有协议证明时可调用，当前 unhealthy 则显示探测失败。路由页面保留配置来源数，并单独展示可调用候选数；对外目录按调用者项目策略和既有团队权限筛选。同名模型不同上游可分别失效；公开目录按逻辑名合并来源。调用历史与当前目录是不同视图。

目录表及保守归属回填为事务迁移 946；同步审计及联调新增的大表索引通过独立无事务迁移 947 并发建立。同步快照和审计记录在同一数据库事务提交；租约以渠道为范围，覆盖多控制面实例，并在提交时复核租约、渠道配置及凭据。人工状态修改串行于同一渠道锁。失败任务保留最近成功时间和回执，单独记录失败原因；审计只包含来源、时间、标识和计数，不写凭据。

## 安装、升级与恢复

先核对同目录 `.run.sha256`，执行安装包 `--verify-only`。首装直接运行 `.run`；已有受管安装按现有 `.run` 原地升级入口执行。自解压包含静态 Docker、Compose、应用及必需镜像、初始化和全部迁移、配置模板、SBOM、镜像 provenance 和源码身份。不得使用生产 .env、数据库或私钥制作交付包。

升级前记录当前入口、服务镜像、受管 current 指针和开发发布回执；使用既有备份流程保留数据库、持久数据、配置和旧镜像。在隔离副本核对迁移和旧应用对新增 schema 的兼容，再用最终同一份安装包升级。升级后核对账号、配置、集成、历史数据、目录、普通/流式调用、阻断和审计，不能仅以健康接口作为验收。

普通回退执行 `sudo jjdctl rollback` 和 `sudo jjdctl status`，保留升级后迁移和业务写入。不要删除数据卷。灾难恢复是单独操作：先保存当前失败状态，并仅在已明确接受备份之后写入丢失的环境执行 `jjdctl disaster-restore --confirm-data-loss`；生产任务不自动执行有损恢复。恢复演练在隔离验证环境执行。命令的完整选项以包内 `jjdctl help` 与既有安装/升级说明为准。

离线安装不访问公网制品源。外部模型同步和调用需要到所配置上游的网络与有效凭据；完全离线推理需另行接入内网模型。已执行的系统、架构、安装/升级/恢复矩阵和制品 SHA-256 以本次交付验收报告为准，不能扩展宣称未实测的系统或架构。

开发发布接管同时支持控制台热更新的前序回执链：版本由受摘要约束的 manifest 核对，沿受保护指针追溯整套网关与回退依据，升级前复核整条链。旧运行态显式配置的安全结果响应头标志在原 `.env` 缺失或为空时保留；已有非空配置优先，不因新基础 Compose 的默认值改变现有集成。
